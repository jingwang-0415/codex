# 页面与交互模式

## 1. 默认视觉系统

- 使用 16:9 画布；HTML 推荐设计尺寸 `960 × 540`，通过整体缩放适配窗口。
- 使用黑、白、灰为主，红色仅标记观点、关键结果和当前焦点。
- 保持同层级字体、标题、页边距、栏宽和底部结论一致。
- 卡片圆角不超过 8px；不要嵌套卡片，不要把整段页面做成仪表盘。
- 不使用装饰性渐变球、发光圆点、无意义插画或大段小字说明。
- 固定格式元素要有稳定尺寸，动态状态不能引发布局位移。

## 2. 页面模式

### 封面

只放主题、汇报人、时间。推荐两种构图：

- 对角平衡：标题中部偏左，第二行强调，信息右下，小型角标平衡画面。
- 横向中轴：单行标题居中，短线与信息置于下方。

不要放目录、能力主线、证明重点、软件研发能力汇报等解释文字。

### 个人简介

展示能力轨迹，不复述领导已知的履历。若能力时间重叠，使用能力带或泳道；不要强行绘制严格折线。照片只占辅助位置，不能挤压成长主线。

### 案例页

- 顶部：章节层级 + 观点标题。
- 中上：完整但克制的背景与目标。
- 主体：动作和效果占主要面积。
- 底部：全页统一的观点结论。

当一页包含多个子问题时，保持等宽主区域，但为每类问题选择不同证据图形。

### 总结页

三栏可对应主体能力，但每栏只写“已有积累 + 下一步精进”。不要再放全篇总述句，避免与卡片内容重复。

## 3. 互动模式

默认从第三页开始启用逐项唤醒：

- 初始状态：核心内容灰化，背景、标题和结论保持可读。
- 点击内容块：单独唤醒或取消。
- `1`–`9`：直接聚焦当前页对应主题。
- `0` 或 `Esc`：恢复当前页总览。
- `→`、`Space`、`PageDown`：依次唤醒，全部讲完后进入下一页。
- `←`、`PageUp`：反向退回，直至恢复灰化后再返回上一页。
- 点击页面空白：进入下一页；点击内容块不能触发翻页。
- `F`：切换全屏；全屏时隐藏底部控制条。

用 `data-reveal` 和 `data-reveal-item` 标记交互范围，避免在脚本中硬编码页码和具体 class。

## 4. 版本组织

建议保留：

```text
outputs/
├── report-static.html
├── report-interactive.html
└── report-web/
    ├── index.html
    ├── styles.css
    ├── app.js
    └── assets/images/
```

- 静态版用于审阅和打印。
- 单文件交互版用于直接打开演示。
- 模块化 Web 版用于持续扩展和替换资源。

修改公共内容时同步三版；使用脚本或 `cmp` 验证关键文案、样式和图片一致。

## 5. 视觉验收

逐页检查：

- 标题是否单行稳定，章节编号、分隔符和主标题字号是否一致。
- 文字是否被折线、箭头、边框、图片或交互放大状态遮挡。
- 长词、指标和节点是否在窄列中换行合理。
- 左右栏、三栏、底部结论和照片区域是否对齐。
- 箭头是否拥有独立空间，不伸入下一节点或被容器裁切。
- 图片是否真实加载，前后对比尺寸和风格是否一致。
- 全屏与普通窗口是否保持 16:9，控制条是否按约定隐藏。
- 动画聚焦是否只改变强调，不改变布局尺寸。

能够使用浏览器或渲染器时，至少检查普通窗口和全屏两种状态，并测试所有键盘路径。若环境阻止视觉自动化，明确说明限制，仍需完成结构、脚本和资源校验。
