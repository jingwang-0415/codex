# 案例输入模板

让用户按案例填写，允许先提供不完整材料。不要要求一次写成汇报文案。

## 基本信息

- 案例名称：
- 时间或版本：
- 业务背景：
- 目标或验收标准：
- 涉及系统与参与方：
- 我的角色和直接责任：

## 难点与判断

- 原始问题或业务现象：
- 为什么普通做法不够：
- 我识别出的关键矛盾、边界或风险：
- 当时有哪些信息不完整或依赖未确定：

## 我的动作

- 我先观察或验证了什么：
- 我做出的核心判断：
- 我比较过哪些方案，为什么选择当前方案：
- 我采取的关键技术或协作动作：
- AI 在哪个具体步骤提供帮助，人工负责什么判断：
- 如何验证方案有效：

## 结果与证据

- 最终结果：
- 优化前指标：
- 优化后指标：
- 数据量、并发、硬件和测试条件：
- 提前发现的风险或问题数量：
- 节省的时间、减少的返工或覆盖范围：
- 形成的文档、流程、Skill、基线或公共能力：
- 是否在其他人或团队中复用：

## 反思与迁移

- 这个案例体现了我工作方式的什么变化：
- 哪个动作最能区分“完成任务”和“主动解决问题”：
- 这套方法还能迁移到哪些场景：
- 下一次还需要提升什么：

## 输入注意事项

- 不清楚的数字写“待确认”，不要估算。
- 行业 Benchmark 单独标注来源和测试条件。
- 明确哪些是个人动作、哪些是团队共同结果。
- 保留失败、方案变化和风险暴露过程，它们通常最能证明判断与推进能力。
